# Caixa financeira: reconciliação Git em rascunho

Esta DRAFT depende da PR 174 e das dependências 173/172/170. Porta a rota de atendimento financeiro já existente na API 80942 e somente seu import/mount protegido no index. Não cria campos, CRUD ou política novos, não substitui a API produtiva e não ativa envio.

O middleware auth do pai verifica JWT antes de preencher req.user; a chave estática recebe role admin com ID api-user. O mount exige auth e adminOuFinanceiro; o guard interno exige role literal admin/financeiro e ID em formato UUID. Assim a chave estática desse middleware é negada pelo guard interno. Isso não prova sessão humana, usuário ativo ou revogação de JWT em tempo real. Cache-Control no-store é aplicado quando a requisição chega ao router, não aos bloqueios anteriores do auth.

Os GETs preservam a projeção/limite da origem e histórico por telefone e instância. GET /:id retorna o contato completo da consulta select('*'); presença de campos e DTO real não foram homologados. A retomada da IA mantém os bloqueios por runs/envios manuais pendentes, CAS de estado/versão e resposta409 em recibo vazio. Recibo de erro não confirma que nada foi escrito.

O POST mantém horário/DNC/canal, estado de conexão, passagem para humano, intenção durável antes do provedor e orçamento existente. Timeout ou recibo incerto preserva uncertain, sem segundo POST automático. Repetir intenção pode fazer leituras e nova marcação humana antes de409: não significa ausência de escrita. Fixtures com claimed/status em memória não provam UNIQUE, concorrência, atomicidade ou entrega. Não foi criado atendimento nem enviado WhatsApp para testar.

O ID do operador é validado, mas não é persistido no claim manual ou na retomada. Atribuição/auditoria do operador exige contrato de schema próprio; este recorte não inventa coluna. Este router não oferece resolução de reserved/uncertain: os estados continuam bloqueando envio/retomada até reconciliação autorizada. Falha ao atualizar o recibo pode preservar reserved; não é rollback nem prova de que o provedor não recebeu. Não foi investigada ausência universal de outros mecanismos administrativos e não foi criada liberação automática.

A consulta de pendências e o CAS do PATCH não são uma operação atômica conjunta; uma reserva concorrente pode surgir entre elas. Atualização de human:true antes de detectar duplicata também muda a versão e pode conflitar com outro operador. Erro de single() em ID ausente pode seguir503 herdado, não404. Formato/precisão/offset do DTO temporal e comparação no banco não foram homologados; hipótese de409 por formato não foi comprovada. Esses pontos são gates de merge/deploy, não regras alteradas neste pacote.

Quatro dependências relativas já existentes foram conferidas iguais após normalizar EOL e preservadas. Index recebe duas inserções reversíveis; package uma linha, lock/dependências intactos. O snapshot usa junction validada para dependências locais existentes, sem instalação ou alteração do checkout com WIP.

A suíte de origem usa Router/DB/provedor/janela/DNC fictícios. A suíte nova carrega router, auth e adminOuFinanceiro reais em VM e usa Express Router real, com verificação JWT e interfaces de negócio fictícias. O trecho real de mount do index é avaliado sem inicializar servidor, porta ou parser HTTP. Cobre bloqueios nas quatro ações, GETs de admin/financeiro, escopo do histórico, CAS vazio/sucesso, dados inválidos e erro de armazenamento fixo. Não é teste de criptografia JWT, sessão real, RLS/grants, PostgREST, node-cron, modelo ou rede. O preload fetch/http/https não é sandbox universal.

Antes de merge/deploy: schema/UNIQUE/FK/grants/RLS/triggers, dados/DTOs, janela e DNC reais, autorização de operações financeiras, identidade/canal/ownership, recibos e concorrência, custo/limites e paridade restante das dependências. Os catálogos anteriores de recovery/ownership/journal são escopados e não devem ser repetidos para fabricar homologação. Referências SQL existentes não autorizam execução. Sem SQL, credenciais/env/flags, modelo, job, chamada, mensagem ou deploy reais neste recorte. O saldo positivo informado pelo humano não comprova chave substituta ou retomada da IA.
